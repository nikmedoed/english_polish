# Работа с проектом

Перед изменениями прочитай materials/ВВОДНЫЕ.md: это единый источник требований, учебной логики и плана. Не создавай параллельные вводные.

При генерации, добавлении или исправлении заданий обязательно прочитай раздел «Генерация и ревью заданий» и следуй ему, включая автоматически созданные варианты.

При изменении схемы банка, механик, проверки ответов, сложности, помощи или правил генерации обнови соответствующие разделы вводных в том же изменении. Удали устаревшие положения вместо противоречащих приписок. При добавлении только примеров методику переписывать не нужно. Повторяемый дефект превращай в редакторское правило и, где возможно, автоматическую проверку.

Карточки банка редактируй только в content/exercises/: один файл на поднавык, файлы перечислены по алфавиту в content/exercises/index.mjs. Сохраняй явные ID и семейства; проверка требует порядок по номеру семейства. Существующие ID и семейства не меняй. Упражнения раздела «Правила» редактируй в content/rules.mjs. dist/ генерируется; runtime-банк собирается в dist/data/bank.json. Не создавай копию в public/data/.

Сырые записи и личные экспорты строго приватны. Используй обезличенные выводы materials/errors/ и materials/monitoring/, а не цитаты или личные обстоятельства. Архив под игнором.

Перед завершением изменений банка или движка: npm run check:content, npm test, npm run check:privacy, npm run build. Для изменённых механик проверь действие в браузере, desktop/mobile по возможности; используй ?sandbox=1. Не выдавай проверку схемы за редакторское ревью. Кратко сообщи результат проверок и реальные ограничения.
