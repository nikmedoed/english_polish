# Все вводные проекта

Единственный документ целей, требований, структуры, учебной логики и плана. Вводная и все сопутствующие материалы собраны в родительской папке `materials/`: обезличенные карточки в `errors/`, срезы в `monitoring/`, сырые записи только в приватной `private/`.

## Цель и требования пользователя

Натренировать основные провалы в английской речи до самостоятельного применения. Одна тема за раз; переход вручную по результатам и проверке в собственной речи. Свободная по длительности тренировка: от пары заданий до любого количества, возможность остановиться в любой момент. Без наказаний за пропуски и обязательных серий дней.

- Single page на GitHub Pages, desktop и mobile.
- Большой пополняемый банк с разными механиками; движок сначала, расширение поэтапно.
- Память, кеш, разные браузеры. Минимум экспорт/импорт; позже аккаунтная синхронизация.
- Новые транскрибации каждые 2–4 недели; входящие и архив партий.
- Мониторить частоту ошибок, практику и перенос в речь; пересматривать приёмы по новым данным.
- Аналитика и учебные данные публикуются в репозитории для разработки персонального решения.
- Сырые разговоры и личные истории строго приватны, хранятся в архиве.
- Префикс файла анализа — критичность, а не порядковый номер.
- Корень репозитория минимален. Сложные идеи фиксировать в плане.

## Персональный профиль

Исходный срез и ограничения проверки: [monitoring/2026-10-02.md](../monitoring/2026-10-02.md).

Основной сигнал: базовая грамматика теряет устойчивость в спонтанных длинных ответах. Словарный диапазон позволяет выражать сложные идеи; приоритет — автоматизация глагольного каркаса и законченных фраз. Короткие предложения снижают нагрузку, не ограничивая сложность мыслей.

| Критичность /99 | Группа | Задача и уверенность |
|---|---|---|
| 97 | Формы глагола | Повторяется в разных месяцах. Разделять be, согласование, did/will + V. |
| 94 | Структура | Вопросы, тезис → причина → пример. ASR мешает оценке длинных ответов. |
| 88 | Именные группы | Сильный сигнал another/other; артикли и число уточнять. |
| 82 | Глагольные модели | Modal + V, to + V; prep + -ing — дополнительная гипотеза. |
| 78 | Сочетания | Think about, discuss + объект, apply for / apply to. |
| 70 | Точность слов | Fame/famous, сравнительные формы. Частотность не доказана. |
| 66 | Местоимения | Второй круг; самокоррекция не равна нескольким ошибкам. |

Баллы — экспертный приоритет, не процент ошибок или уровень языка. Публичная аналитика сохраняет обоснование и уверенность, без личных историй и дословных цитат. Учебные иллюстрации написаны заново. Исходные записи остаются локально в архиве.

## Структура

- `materials/README.md`: карта материалов и граница приватности.
- `materials/docs/ВВОДНЫЕ.md`: единый документ вводных и плана дальнейшей работы.
- `materials/errors/`: только обезличенный анализ ошибок. Имя файла начинается с балла критичности.
- `materials/monitoring/`: исходный срез и новые отчёты по датам и периодам. Только обезличенные показатели и выводы.
- `materials/private/archive/2026-10-02/`: 22 исходные записи и manifest с SHA-256. Новые партии в отдельных папках дат. Полностью исключено из Git.
- `materials/private/inbox/`: входящие записи; после проверенного архивирования папка освобождается. Личные экспорты хранятся в `materials/private/`.
- `content/`: редактируемые задания; `public/`: приложение; `scripts/`: сборка, приём записей и проверки; `tests/`: тесты; `.github/`: Pages.
- `dist/`: целиком генерируется при сборке и исключён из Git. Банк заданий создаётся сразу в `dist/data/`; исходники в `public/` сборка не меняет. Задания редактируются только в `content/`.

Один актуальный комплект аналитики. Старые копии анализа и временные инструменты не входят в рабочую структуру. Сырые записи никогда не попадают в публичные отчёты. Игнор не скрывает уже отслеживаемые файлы; проверка приватности контролирует Git-пути и признаки сырых записей.

## Повторение правил

Отдельный раздел «Правила» перед практикой: 20 коротких блоков и 60 авторских вопросов в `content/rules.mjs`. Основные времена: Present Simple/Continuous, Past Simple/Continuous, Present Perfect, will + V и Future Continuous; отдельно be. Остальные блоки охватывают вопросы, связки, определители, артикли, модели глагола, сочетания, части речи и местоимения. Это приоритетный старт, не полный справочник всех времён.

Блок: вспомнить схему → узнать конструкцию → применить правило. Три вопроса без клавиатуры и таймера; памятка по запросу, повторный выбор после ошибки, памятка после двух ошибок, разбор после верного ответа. Пропуск и выход доступны всегда; переход ручной. Итог считает только первые верные ответы без памятки. Можно повторить блок или перейти в практику выбранной темы. Правила не являются семействами банка, не влияют на интервалы, адаптацию и готовность. Прогресс блока хранится только в sessionStorage вкладки, отдельно для sandbox; после перезагрузки текущий вопрос повторяется без зачёта незавершённого ответа. Долговременной истории и переноса этих результатов в экспорт пока нет.

Вопросы редактируются только в content/, проверяются check:content и сборкой. Для правил редактор проверяет одну принимаемую формулировку, ложность остальных вариантов именно для условия, связь схемы со смыслом. Не выдавать охват всех тем за полноту всех поднавыков или доказательство усвоения.

## Практика сейчас

- Тренировка без лимита заданий и промежуточных остановок. Полная практика или режим без клавиатуры; количество не настраивается.
- Один фокус. Темы меняются вручную, без автоматического перехода по проценту.
- Самостоятельная фраза — семейство. Варианты механик не считаются независимыми примерами.
- Новые фразы смешиваются с подошедшими повторениями, механики чередуются. Семейства не повторяются до исчерпания доступного пула выбранного режима; затем начинается новый круг, по возможности без немедленного повтора последней фразы.
- Старт с контекстных заданий уровня 3. Ошибка снижает сложность только соответствующего поднавыка; две ошибки подряд дают опору. Три успешных самостоятельных ответа возвращают уровень 3. Устное завершение добровольно: русский стимул, английский образец после ответа.
- Верный ответ: результат и разбор остаются до кнопки «Следующее» или отдельного Enter. Старые настройки быстрого перехода однократно переводятся на ручной режим (preferences.reviewVersion = 1). В настройках можно явно включить переход через 8 секунд только для короткого верного ответа без подсказки и опечатки; составные контексты и исправления всегда переходят вручную. Пауза сохраняет разбор. Ошибка: самостоятельное исправление, затем намёк, затем образец при дальнейших затруднениях; другая фраза на тот же поднавык после двух заданий; при ручном завершении проверка сохраняется для следующего подхода.
- Пропуск без штрафа; помощь учитывается отдельно. Итоги только по кнопке «Закончить», продолжение по выбору. Во время работы видна текущая статистика без шкалы до конца.
- Сначала выдаются новые и подошедшие к сроку фразы. Когда они закончились, тренировка автоматически продолжается ранней практикой; она не доказывает удержание и не увеличивает интервал в тот же день.
- Сессия и черновик сохраняются в текущей вкладке; новый календарный день начинает новый подход.

Повторение по семейству: ошибка или опора → 10 минут; самостоятельный успех → 1, 2, 4, 8, максимум 14 дней. Успехи в тот же день не увеличивают интервал. Устная самооценка не откладывает проверяемые задания. Дополнительная ранняя практика не доказывает удержание.

## Метрики

Общая точность включает выбор и сборку без подсказок. Самостоятельное воспроизведение: пропуск, исправление, преобразование, ограниченный перевод и контраст контекстов без опоры. Признак готовности использует последнее наблюдение на семейство в календарный день, максимум 20: минимум 12 наблюдений, 6 разных семейств, 3 дня, 4 семейства успешно проверены спустя ≥24 часа, точность ≥85%, минимум 4 контекстных семейства и 3 глагольных поднавыка (2 для остальных тем). Это рабочая эвристика, не доказательство переноса в разговор.

Опора, устная самооценка и немедленные повторы не повышают готовность. Перед сменой темы нужна собственная короткая речь и проверка на новых примерах. Независимый контроль пока в плане ниже. Произношение и связность автоматически не оцениваются.

Для транскрибаций: подтверждённые ошибки / вручную проверенные возможности употребления целевой конструкции. Дополнительно учитывать объём собственной речи, длительность, тему, ASR и долю проверенной речи. Недостаточную выборку обозначать явно. Связь практики с динамикой не считать доказанным причинным эффектом.

Примеры используют контраст контекстов, преобразования, перевод, исправление, пропуски и выбор; производные варианты остаются в том же семействе. Источник `content/bank-source.mjs`: предложение с пропуском, ответ, неверный вариант и объяснение; отдельно русские смысловые стимулы. До перехода к явным ID добавлять строки в конец, не переставлять.

Не помечать допустимую эмфазу, британскую норму или альтернативный союз ошибкой. Регистр, пунктуация и стандартные сокращения не влияют на проверку. Исправление сохраняет смысл и нейтральный порядок; произвольное перефразирование пока не оценивается. Неоднозначную карточку переписывать, а не ужесточать сравнение.

## Новые партии

Положить txt/md/vtt/srt в `materials/private/inbox`, запустить `npm run intake`. Команда копирует в новую партию архива, проверяет байты, создаёт manifest и файл мониторинга в `materials/monitoring/`; затем удаляет обработанные копии из inbox. Архивные партии не перезаписывать.

Далее: проверить говорящего и ASR → подтвердить паттерны и знаменатели → сопоставить с практикой → обновить публичную обезличенную аналитику → написать и вычитать задания. Архив не загружать в GitHub. Автоматический семантический анализ пока не реализован. Публично можно хранить проверенные агрегаты, уверенность и выводы для персонализации.

## Память и публикация

Статический сайт без сервера данных, регистрации и CDN. LocalStorage: тема, настройки, ID ответов, время, длительность, результат, самооценка, использование опоры. Текст ответов не попадает в историю или экспорт. Черновик текущего ввода сохраняется только в sessionStorage текущей вкладки; аудио не записывается. Импорт объединяет ID, сохраняет тему и настройки принимающего браузера; история старых заданий допускается. Повреждённый импорт не применяется. Экспорт — личный резервный файл.

Chrome-аккаунт сам не синхронизирует данные сайта. Расширение и облачная кросс-браузерная синхронизация — следующие этапы. При недоступном хранилище показано предупреждение.

Service worker: HTTPS/localhost, первый запуск онлайн, приоритет сети и офлайн-кеш. При изменении увеличить версию кеша; перезагрузить уже открытую страницу после сборки. Относительные пути поддерживают подпапку Pages. Сборка очищает dist и копирует явный список приложения; личные файлы и аналитика в сайт не попадают. Workflow проверяет приватность, тесты и сборку. Remote и публикация ещё не настроены.

## Проверка без изменения основной статистики

Локально открыть `http://localhost:4173/?sandbox=1#practice`: отдельные ключи памяти и сессии, явная пометка тестового режима. Для экспорта доступны скачивание JSON и ручной перенос текста; импорт принимает файл или вставленный JSON. Это резервный путь для браузеров с ограничением загрузок.

В заданиях с вводом пропуска есть русский смысл и исходное слово либо тип требуемого элемента. Это снимает неоднозначность свободного пропуска (например, discuss/send/prepare) и проверяет целевую форму, а не угадывание авторского глагола. Такой словарный стимул не считается показом грамматического ответа. В исправлении требуется сохранить остальные слова; свободное перефразирование — отдельная будущая механика.

## Интерфейс и предпочтения пользователя

Компактная, аккуратная, структурированная раскладка без крупных лозунгов, избыточного воздуха и текстовой воды. Основной текст 14 px, заголовки 19–22 px, предложение задания 18–20 px. Короткая инструкция рядом с действием; дополнительные пояснения раскрываются по запросу. Без длинных тире в интерфейсе. Темы и результаты показывать в таблицах с выровненными столбцами. Экспорт и импорт находятся в «Прогрессе»; в «Настройках» сложность и автопереход. Способ ответа переключается в практике.

## Учебные основания

Разнообразное извлечение из памяти и перенос правила в изменённый контекст: [The role of variable retrieval in effective learning, PNAS](https://doi.org/10.1073/pnas.2413511121). Короткая распределённая практика и обратная связь по конкретной ошибке: [APA: Practice for Knowledge Acquisition](https://www.apa.org/education-career/k12/practice-acquisition).

Применение в движке: ответ без показанного варианта; чередование форм и контекстов внутри одного фокуса; объяснение целевого правила после ошибки; самостоятельное исправление; последующая проверка на другой фразе и в другой день. Сложность задаётся конструкцией, а не редкой лексикой. Нет гонки на время или обязательного бесконечного продолжения. Интервалы, необязательные 8 секунд автоперехода и пороги адаптации являются настройками проекта, а не установленными исследованиями оптимальными значениями. Точные альтернативы проверяются по авторскому списку; свободный смысловой ответ пока не оценивается.

## Быстрый переход и разбор

После проверенного ответа Enter сразу открывает следующий вопрос; добровольная устная фраза возвращает к итогам. Enter в поле сначала проверяет ответ; ошибку нужно исправить либо явно пропустить исправление. Автопереход можно приостановить. Статус сначала явно сообщает «Верно» или «Пока неверно». Помощь поясняется отдельно: пользователь открыл подсказку, приложение показало её после ошибки либо был раскрыт ответ. Сам выбор из вариантов не считается использованием подсказки; запрос привязан к ID текущего задания. Старые события помощи сохраняются без попытки выдумать причину. Составные ответы показываются отдельными предложениями с выделением формы. После проверки результат получает фокус и прокручивается в видимую область, включая мобильный экран. Предыдущий вопрос, результат и ответ остаются отдельной приглушённой карточкой: ниже текущего на десктопе, выше на мобильном; пояснение видно сразу. Последний разбор доступен и после завершения подхода. Текст ответа сохраняется только в сессии вкладки, не в публичной истории или экспорте. Пояснения должны связывать форму со смыслом, ситуацией употребления и уместной альтернативой.

## Удобство режима и опечатки

В заголовке практики переключатель из двух кнопок: полная практика (чередование ввода и нажатий) и без клавиатуры (выбор, сопоставление, сборка). Отдельной строки, выпадающего списка и режима «только ввод» нет. Старые сохранённые настройки «только ввод» переходят в полную практику. В полной практике после двух заданий одного способа выдаётся другой способ. Сложные задания на выбор проверяют преобразование всей фразы и контексты. В сопоставлении крупное английское предложение содержит компактный выбор непосредственно на месте пропуска; варианты можно использовать повторно. Пять семейств привычки/процесса (101, 102, 107, 112, 121) содержат четыре контекста; в сопоставлении их порядок перемешивается и сохраняется при исправлении и перезагрузке. Остальные пары требуют отдельного редакторского расширения. В режиме без клавиатуры можно повторить выбор с постепенной помощью или пропустить, без обязательного печатного исправления.

Одну опечатку в нецелевом слове полного ответа можно принять и подсветить: замена, пропуск, лишняя буква или перестановка соседних букв. Целевая форма, служебные слова, изменения окончаний и ответы в коротких пропусках проверяются строго. Принятый ответ не требует повторного ввода. Это ограниченная эвристика, не универсальная проверка свободного текста.

## Ступени помощи после ошибки

Первая ошибка фиксируется один раз, но правильный ответ не раскрывается: можно самостоятельно исправить свой сохранённый ввод. После неудачного исправления появляется намёк на правило, после следующего раскрываются образец и разбор. Намёк можно запросить сразу; после намёка образец также доступен отдельной кнопкой. Повторные попытки не увеличивают число заданий и не превращают исходную ошибку в независимый успех. Самокоррекция и исправление с опорой различаются в результате. В режиме без клавиатуры повторный выбор и сопоставление также обходятся без ввода. Пропуск доступен на каждом шаге.

Опечатки показываются явно: «Ты написал» и «Правильно», с выделением конкретных отличающихся букв. Принятую опечатку можно увидеть в текущем и предыдущем разборе. При опечатке результат остаётся до ручного перехода. При раскрытом разборе неправильного полного ответа выделяются отличающиеся слова, если число слов совпадает.

В предыдущем разборе объяснение видно сразу под правильным ответом, без спойлера и дополнительного клика.

Справа в практике только статистика и ссылки. Правило текущего задания показывается у самого задания по кнопке «Подсказка» или «Намёк»; запрос опоры учитывается явно. Дублирующего спойлера с правилом в статистике нет.

## Генерация и ревью заданий

### Источник и учебная цель

Перед партией прочитать этот раздел, актуальный разбор целевой ошибки в materials/errors/ и последний подходящий срез мониторинга. Выбрать один фокус и конкретные поднавыки из content/curriculum.mjs. Записать в отчёте партии цель, поднавыки, уровни, число независимых семейств, покрытие способов ответа и ограничения. Не выдумывать измеренную частоту или эффект обучения. Не использовать сырые цитаты, имена, личные истории и обстоятельства; писать новые нейтральные примеры.

### Как спроектировать партию

Начинать с поднавыка и ситуации употребления, а не с шаблонного пропуска. Для глаголов проверять смысл: привычка/процесс, завершённое прошлое/результат сейчас, вопрос/утверждение/отрицание. Внутри одного фокуса менять контекст, лицо, число, время и тип фразы. Смена имени или предмета при неизменном очевидном шаблоне не делает задачу независимой. Для расширения брать новые сочетания контекстов и конструкций.

Предусмотреть доступность без клавиатуры: выбор полной фразы, сопоставление контекстов, сборка. Полная практика включает самостоятельный ввод, преобразование, исправление, ограниченный перевод и контраст. Не строить партию из одних переводов или одинаковых выборов. Нет фиксированного требования «три варианта»: число вариантов зависит от числа правдоподобных ошибок. Опора уровня 1 допустима при затруднениях, но не должна заменять контекстную практику. Уровень 2: самостоятельная целевая форма/исправление; уровень 3: перенос в контекст, преобразование или контраст. Редкая лексика и длинный текст сами по себе не являются сложностью. Устная практика добровольна и учитывается отдельно от проверенного воспроизведения.

### Однозначность и проверка

Один основной проверяемый поднавык на карточку. Для составных задач явно сказать, какие конструкции менять. Из условия должно следовать, почему выбранная форма уместна. Например, предложение «We ___ the fix already» допускает вариативность употребления; если проверяется Present Perfect, явно задать эту конструкцию или переписать контекст. В переводе задать опорные слова и необходимый смысл, не требовать угадывать авторскую лексику. В исправлении и преобразовании указать, что сохранять.

Каждый отвлекающий вариант должен быть ошибочным именно для указанной задачи и отражать реальную путаницу. Нельзя противопоставлять две допустимые нормы, британский/американский вариант, who/that, полное/сокращённое отрицание или просто разные верные перефразы. Самостоятельно решить карточку без просмотра answers, затем проверить все варианты и допустимые ответы. Неоднозначность исправлять в условии, а не запретом правильного ответа. Добавить нормативные альтернативы в answers. Учесть пунктуацию, регистр и сокращения нормализатора. Для контраста и сопоставления проверить каждый контекст отдельно и совместный ответ. Новые сопоставления проектировать из 3–4 коротких контекстов с повторением правильных форм, чтобы оставшийся ответ нельзя было вывести исключением. Порядок допускает перемешивание только при независимых условиях без ссылок «в первом/во втором»; явно отметить shuffleParts. Части остаются одним семейством, а не независимыми наблюдениями.

### Намёк, разбор, опечатка

Намёк на правило хранится у поднавыка в skills.rule: он должен направлять, не давать готовый ответ текущей карточки. explanation показывается в разборе: коротко объяснить смысл, уместную ситуацию, связь с формой и отличие от вероятной альтернативы. Формулы «will be + -ing» и названия времён без смысла недостаточны. Разбор писать понятным русским языком, переводить ключевой контекст и связывать его с конкретным ответом. Например: «В полдень он будет в процессе работы. Поэтому will be working; время начала или завершения здесь не указано». Проверить, что общий намёк подходит всем карточкам данного поднавыка; для узкого правила уточнить поднавык, а не показывать нерелевантную опору.

Соблюдать ступени помощи движка: самостоятельное исправление → намёк → образец. Не вставлять ответ в начальную инструкцию или исходный смысловой стимул. Предыдущий разбор виден сразу, без спойлера. Не требовать повторного ввода принятой опечатки; выделять отличающиеся буквы. Проверить для новых целевых форм, что допуск опечаток принимает случайное написание вроде recieve, но не неверное received после did. При дефекте проверки добавить содержательный тест.

### Где добавлять и какие поля нужны

Основной авторский источник новых карточек: content/curriculum.mjs, helpers transform/repair/translate/contrast и advancedExercises. Старые seeds в content/bank-source.mjs имеют ID по позиции: не переставлять и не вставлять строки в середину. Новые ID явные: topic-skill-number-mode; семейство совпадает с ID без суффикса механики. Не переиспользовать ID для другого вопроса и не выдавать варианты одного семейства за независимые примеры. Использовать свободный номер; проверить отсутствие коллизий.

Обязательные поля карточки: id, family, topic, skill, mode, level, prompt, answers, model, explanation, cue. task обязательно для преобразования и перевода; base для пропуска/перевода. Выбор: choices с единственным принимаемым вариантом. contrast/match: parts с prompt/base/answer, совместный answers через « | »; match также choices, содержащие ответы всех частей без повторов, и ровно один пропуск ___ в каждом предложении. shuffleParts разрешает перемешивание независимых контекстов; автоматическая проверка требует 3–4 части и повторяющиеся ответы. Сборка использует model. protectedWords рассчитываются сборщиком; проверить результат assess на целевой ошибке и опечатке. Не редактировать сгенерированный JSON вручную.

Поддерживаемые механики: choice, gap, repair, order, speak, transform, translate, contrast, match. Новая механика требует вместе: схемы и валидатора, отображения и действий, проверки ответов, выбора/адаптации, учёта статистики, импорта/экспорта, тестов, обновления этих инструкций. Не обещать свободную семантическую оценку: пока проверяются перечисленные нормативные ответы.

### Приёмка и поддержание инструкций

После генерации провести редакторское ревью каждой независимой карточки и её производных вариантов. Проверить грамматику, смысл, естественность, альтернативы, качество отвлекающих вариантов, короткий разбор и совместимость с обоими пользовательскими режимами. Черновик с сомнениями не включать в опубликованный банк; спорные решения и недостающие механики фиксировать в плане здесь.

Выполнить npm run check:content, npm test, npm run check:privacy, npm run build. При изменении механики пройти её в sandbox-браузере: ответ, ошибка, самокоррекция, намёк, образец, опечатка, Enter, переход и предыдущий разбор; проверить мобильную ширину. Для добавления примеров достаточно репрезентативной проверки новой партии, но все варианты должны быть вычитаны. Схема и тесты не доказывают педагогическое качество.

При изменении учебной логики обновить существующие разделы этого документа в том же изменении. При добавлении только примеров сверить инструкцию; обновить объём и описание партии при необходимости. Повторяющиеся дефекты превращать в правила и проверки. AGENTS.md закрепляет этот порядок для следующих сессий агента. Не создавать отдельные конкурирующие инструкции.

### Пример добавления нового семейства

Вставить авторскую карточку в content/curriculum.mjs рядом с задачами нужного поднавыка; перед выбором номера проверить свободный ID. Например:

```js
transform(
  'verbs-past', 201,
  'The engineer found the missing cable yesterday.',
  'Сделай общий вопрос. Сохрани остальные слова.',
  'Did the engineer find the missing cable yesterday?',
  'Спрашиваем о завершённом событии вчера. Did уже обозначает прошлое, поэтому find, не found.'
);
```

Это пример записи, а не автоматически принятая учебная карточка: перед добавлением сравнить с существующими заданиями, чтобы новая фраза расширяла практику, а не только меняла существительные. Сборщик сам добавляет вариант choice для нового transform/repair и match для contrast, если family относится к явному skill-ID. Производные варианты обязательно проверяются отдельно; их количество не увеличивает число независимых семейств. Перевод не получает автоматически выдуманных отвлекающих вариантов: для покрытия без клавиатуры добавить отдельную вычитанную контекстную задачу. Проверка банка встроена в сборку и поэтому в публикацию Pages.
